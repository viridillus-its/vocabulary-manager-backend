# 単語帳アプリケーション 要求事項書

---

## 1. 目的

本システムは、ユーザーがアップロードした単語データ（単語と意味のペア）をもとに、効率的に単語学習を行うことを目的とした Webベースの単語帳アプリケーションです。

フロントエンドは Python の Dash フレームワーク、バックエンドは API 方式で別リポジトリとして連携します。

---

## 2. システム構成概要

### 2.1 全体構成

| 層                     | 通信         | 次の層               |
|------------------------|--------------|----------------------|
| ユーザー               | ↓ Web UI     | フロントエンド（Dash） |
| フロントエンド（Dash） | ↓ HTTP API   | バックエンド          |
| バックエンド           | ↓            | データ保存領域        |

### 2.2 役割分担

| 区分         | 主な責務                                 |
|--------------|------------------------------------------|
| フロントエンド | 画面表示、入力受付、画面遷移、API呼び出し |
| バックエンド   | データ処理、学習ロジック、正誤判定、永続化 |

---

## 3. 想定ユーザー

- 単語学習を行いたい一般ユーザー
- 学習用の単語データを Excel ファイルとして用意できるユーザー

---

## 4. 機能要件（フロントエンド）

### 4.1 共通要件
- Python Dash フレームワークを使用
- サイドバーによるメニュー選択型 UI
- バックエンドとは HTTP API で通信

### 4.2 画面構成

#### 4.2.1 ホーム画面
- アプリケーションの概要説明を表示
- 単語学習の基本的な使い方を説明
- サイドバーメニューの役割を説明

#### 4.2.2 問題解答登録画面（ファイルアップロード）
- ユーザーが Excel ファイルをアップロードできる
- アップロード結果（成功／失敗）を表示
- ファイル形式の簡易チェック

#### 4.2.3 学習画面
- 出題される単語を表示
- 4択の選択肢を表示
- ユーザーが選択肢を選べる
- 正解／不正解の結果を表示
- 「次の問題」へ進む操作

#### 4.2.4 学習履歴画面
- 学習履歴の一覧を表示
- 学習回数・正答率などを確認
- 必要に応じて簡易グラフを表示

---

## 5. 機能要件（バックエンド）

### 5.1 ファイル処理
- ユーザーがアップロードした Excel ファイルを受け取る
- ファイルを解析し、単語データに変換
- 不正なデータを検証・除外

### 5.2 単語データ仕様

#### 5.2.1 Excel ファイル形式

| 列 | 内容         |
|----|--------------|
| A  | 単語（問題文）|
| B  | 意味（解答） |

- B列は解答の全集合として扱う

### 5.3 学習ロジック
- 出題する単語をランダムまたは規則に基づいて選択
- 正解は B 列の該当データ
- 選択肢は以下のルールで生成

**4択生成ルール**
1. 正解の意味（B列）を1つ取得
2. B列全体からランダムで3つ取得（正解を除外）
3. 正解を含めて4択とする
4. 選択肢の順序をランダムにシャッフル

### 5.4 正誤判定
- ユーザーの選択肢と正解を比較
- 判定結果を保存
- 判定結果をフロントエンドに返す
> ※ 正解データはフロントエンドに直接送信しない

### 5.5 学習履歴管理
- ユーザーごとの学習履歴を保存
- 正答／誤答、日時、回数を記録

---

## 6. API 要件（概要）

| メソッド | エンドポイント         | 内容                     |
|----------|-----------------------|--------------------------|
| POST     | /api/upload           | 単語ファイルのアップロード|
| GET      | /api/study/next       | 次の問題を取得           |
| POST     | /api/study/answer     | 解答送信・正誤判定        |
| GET      | /api/history          | 学習履歴取得             |

---

## 7. 非機能要件

### 7.1 セキュリティ
- 正解データはフロントエンドに返さない
- 不正なファイルアップロードを防止

### 7.2 拡張性
- 出題ロジックを将来的に改善できる構成
- 記述式問題への拡張を考慮

### 7.3 保守性
- フロントエンドとバックエンドの責務を明確に分離
- 学習ロジックはバックエンドに集約

---

## 8. 制約事項
- フロントエンドは Dash フレームワークを使用
- バックエンドは別リポジトリで管理
- 本要求事項書は初期フェーズの要件をまとめたものであり、詳細仕様は別途定義
